# Coding Style

## 原则

* 优先简单、直接、可读。
* 当前需求优先，不要脑补未来需求。
* 修改前先看附近已有代码，保持项目现有风格。
* 能用普通 `if` / `for` / `return` 写清楚，就不要用复杂表达式、链式调用、三元套三元、过度封装。
* 允许少量重复代码，不要为了消除重复而过早抽象。
* 不要提前设计扩展点，不要创建当前需求用不到的接口、策略类、工厂、工具函数。
* 变量名和函数名要直白，能看出业务含义。
* 注释只解释业务原因和特殊规则，不要解释代码本身。

## 修改范围

* 只改和当前需求直接相关的代码。
* 不要顺手重构无关代码。
* 不要改变现有接口入参、返回结构、数据库字段含义、权限逻辑，除非需求明确要求。
* 不要引入当前需求用不到的依赖。

# 共保业务（PremiumSplitter）Mock 测试文档

## 1. 背景

基于最新提交 **`feat:Claude 4.6 adds co-insurance business logic.`**（commit: `0d3a14e`），本次新增针对 `PremiumSplitter` 的单元测试，目标是验证“共保比例校验、金额拆分、尾差处理、排序拆分、拆分结果校验”等核心业务规则。

---

## 2. 测试对象与范围

- **测试类**：`org.xiaoxu.al.PremiumSplitter`
- **测试文件**：`co_insurance/src/test/java/org/xiaoxu/al/PremiumSplitterTest.java`
- **测试类型**：单元测试（JUnit 5） + Mock 测试（Mockito）

> 说明：`CoParty` 使用 Mockito mock 对象构造输入，确保测试专注于 `PremiumSplitter` 本身逻辑，不被实体构造细节干扰。

---

## 3. Mock 设计

### 3.1 Mock 粒度

- 通过 `mock(CoParty.class)` 创建共保方对象。
- 通过 `when(party.getShareRatio())`、`when(party.getSortOrder())` 精确控制比例与顺序。

### 3.2 为什么采用 Mock

1. **隔离性更强**：避免实体初始化或未来字段变更影响测试稳定性。
2. **覆盖边界更容易**：快速构造各种比例组合与排序组合。
3. **更贴近业务意图**：测试只关注“输入比例/顺序 -> 拆分结果/异常”。

---

## 4. 已覆盖场景（本次）

> 共 8 个测试场景，覆盖正常路径 + 关键异常路径。

| 编号 | 方法 | 场景 | 输入示例 | 期望结果 |
|---|---|---|---|---|
| TC-01 | `validateRatioSum` | 比例和等于 1（含 6 位小数） | 0.333333 + 0.333333 + 0.333334 | 正常通过 |
| TC-02 | `validateRatioSum` | 比例和不等于 1（超出容差） | 0.50 + 0.40 | 抛 `CoInsureRatioException` |
| TC-03 | `validateRatioSum` | 共保方为空列表 | `[]` | 抛 `CoInsureRatioException` |
| TC-04 | `split` | FLOOR 拆分 + 最后一方承担尾差 | total=100.00, 比例 0.3333/0.3333/0.3334 | 33.33 / 33.33 / 33.34，且总和=100.00 |
| TC-05 | `split` | 总金额非法（<=0） | total=0 | 抛 `PremiumSplitException` |
| TC-06 | `split` | 共保方为空列表 | `[]` | 抛 `PremiumSplitException` |
| TC-07 | `verify` | 拆分和与总额不一致 | total=100, splits=33/33/33 | 抛 `PremiumSplitException` |
| TC-08 | `splitSorted` | 未排序输入自动按 `sortOrder` 排序后拆分 | 输入顺序 3,1,2 | 返回顺序按 1,2,3 对应结果 |

---

## 5. 业务规则映射

### 5.1 比例校验规则

- 规则：共保比例和必须为 `1.000000`（允许容差）。
- 覆盖：TC-01、TC-02、TC-03。

### 5.2 拆分与尾差规则

- 规则：前 N-1 方按 `FLOOR` 保留 2 位；最后一方承担尾差。
- 覆盖：TC-04。

### 5.3 入参防御规则

- 规则：总金额必须 > 0；共保方列表不能为空。
- 覆盖：TC-05、TC-06。

### 5.4 强制校验规则

- 规则：拆分后总和必须严格等于总金额。
- 覆盖：TC-07。

### 5.5 排序便捷规则

- 规则：`splitSorted` 必须先按 `sortOrder` 排序再拆分。
- 覆盖：TC-08。

---

## 6. 当前未覆盖/后续建议场景

以下场景建议在下一轮补齐（本次未实现）：

1. `validateRatioSum` 输入 `null`。
2. 比例为负数或包含 `null` 比例值时的异常语义。
3. 极小金额（如 `0.01`）与多方比例组合的稳定性。
4. 大金额（百万级）及多方（10+）下的精度与性能验证。
5. `splitSorted` 中 `sortOrder` 重复值场景。

## 7. 执行方式

在仓库根目录执行：

```bash
mvn -pl co_insurance -am test -Dtest=PremiumSplitterTest
```

若环境缺少上游模块依赖，可先执行：

```bash
mvn -pl web_boot -am install -DskipTests
mvn -pl co_insurance -am test -Dtest=PremiumSplitterTest
```

## 8. 结论

本次测试已覆盖 `PremiumSplitter` 的核心业务路径与关键异常路径，尤其是“**FLOOR 截断 + 最后一方承担尾差 + 强制校验总和**”这一核心财务规则，可作为后续迭代（例如引入服务层、落库层）时的回归基线。

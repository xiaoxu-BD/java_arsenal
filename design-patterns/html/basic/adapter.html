适配器模式 Adapter 结构型

一句话核心：接口不匹配时加"转接头" —— 手机只认 5V，墙上只有 220V，谁都不用改

交互舞台 · 给手机充电
220V
家用电（被适配者）
祖传代码，不能改
输出接口：output220v()
— 未连接 —
手机（目标接口）
等待充电…
只认 output5v() 接口
核心规则
  • 三个角色：目标接口（手机要 5V）、被适配者（墙上 220V）、适配器（充电头，实现目标接口 + 借用被适配者）
  • 双方都不改：老类动不了/不敢动，新接口要统一，转换逻辑全部消化在适配器里
  • 组合优于继承：对象适配器持有 220V 还能适配它的各种变体；类适配器把唯一的继承名额用掉了
JDK 同款：new InputStreamReader(new FileInputStream(...)) —— 字节流被"适配"成字符流。
代码联动
public class ClassAdapter extends Voltage220      // 继承拿到 220V
        implements Voltage5 {                        // 实现手机要的 5V

    public int output5v() {
        int v = output220v();      // 调父类（被适配者）
        return v / 44;             // 转换成 5V
    }
}
public class ObjectAdapter implements Voltage5 {   // 只实现目标接口

    private final Voltage220 voltage220;            // 组合持有被适配者

    public ObjectAdapter(Voltage220 voltage220) {
        this.voltage220 = voltage220;
    }

    public int output5v() {
        int v = voltage220.output220v();   // 委托给它
        return v / 44;                     // 转换成 5V
    }
}

代理模式 Proxy 结构型

一句话核心：控制对目标的访问 —— 代理和真实对象同接口，能挡的挡（前置），必须转的转（转发），收尾自己扛（后置）

交互舞台 · 你是活动方，先跟谁打交道？
活动方只拿到 Star 接口
经纪人（代理）前置检查 / 挡琐事 / 后置收尾
明星本人只干专业活：sing()
消息会流动到这里（先选下面一个操作）
活动方手里是 Star 接口，根本分不清（也不需要分清）对面是经纪人还是本人 —— 这就是"同接口"的意义。
核心规则
  • 同接口：代理与真实对象实现同一接口，调用方无感切换
  • 三段式：前置（校验/挡请求）→ 转发（专业活给本人）→ 后置（记录/收尾）
  • 意图区分：结构长得像装饰器，但代理是"控制访问"，装饰器是"增强功能"；Spring AOP、MyBatis Mapper 就是代理（见 advanced/proxy 的 JDK 动态代理）
代码联动 · 消息流动时高亮对应行
public class StarAgent implements Star {     // 经纪人：和明星同接口

    private final Star star;                 // 持有真实对象

    public StarAgent(Star star) { this.star = star; }

    public void negotiate() {                // 琐事：代理直接挡下
        System.out.println("经纪人：聊聊档期和报价");
        // 不调用 star，本人无感
    }

    public void sing() {                     // 专业活：三段式
        System.out.println("经纪人：资质检查通过，放行");   // ① 前置
        star.sing();                         // ② 转发给本人
        System.out.println("经纪人：结账收尾");             // ③ 后置
    }
}

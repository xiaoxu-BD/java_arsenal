状态模式 State 行为型

一句话核心：同一操作在不同状态下行为不同 —— 订单不写 if-else，把操作全权委托给"当前状态对象"

// 不用状态模式的订单 —— 每加一个状态，每个方法都要加一层判断： public void ship() { if (status.equals("PAID")) { ... } else if (status.equals("CREATED")) { throw new 不允许(); } else if (status.equals("SHIPPED")) { throw new 已发货还发什么(); } else if (status.equals("COMPLETED")) { ... } // 判断散落各处，改一处漏一处 }
核心规则
  • 状态决定行为：pay/ship/confirm 在"待支付/已支付/已发货"下各有着落，不在当前职责内的直接拒绝
  • 订单只做委托：Order 里没有一个 if(status==…)，全部 state.pay(this) 一行转发
  • 流转规则收进状态类：谁能流转到谁写在状态类内部，新状态 = 新类（对比下方红框 if-else 版）
与责任链的区别：责任链是"沿链找人处理"，状态是"我是什么就怎么响应"。 规则表版状态机（流转集中校验，见 advanced/state 包）更适合纯流程校验场景。
代码联动
public class Order {
    private OrderState state = new CreatedState();

    public void pay()     { state.pay(this); }      // 全权委托
    public void ship()    { state.ship(this); }     // 没有一个 if
    public void confirm() { state.confirm(this); }

    void setState(OrderState s) { this.state = s; } // 状态类内部调用
}

public class CreatedState implements OrderState {
    public void pay(Order order) {
        System.out.println("支付成功");
        order.setState(new PaidState());            // 待支付→已支付
    }
    // ship/confirm 走接口 default：当前状态不允许
}

public interface OrderState {
    default void pay(Order o)   { throw 不允许("pay"); }
    default void ship(Order o)  { throw 不允许("ship"); }
    default void confirm(Order o){ throw 不允许("confirm"); }
}

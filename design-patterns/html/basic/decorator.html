装饰器模式 Decorator 结构型

一句话核心：装饰者和被装饰者实现同一抽象，层层包裹动态增强 —— 加料不用改咖啡的代码

交互舞台 · 点一杯咖啡，随便加料（可以重复加）

核心规则
  • 同一抽象：牛奶、糖、浓缩咖啡都是 Beverage —— 所以"加料后的咖啡"仍是一杯 Beverage，可以继续包
  • 装饰器 = 自己是饮品 + 手里包着一杯饮品：cost() = 自己的加价 + 里层的 cost()，像剥洋葱层层累加
  • 开闭原则：新增"椰果"只需加一个装饰器类，咖啡和旧装饰器零改动；任意组合无需提前穷举
JDK 同款：new BufferedReader(new InputStreamReader(new FileInputStream(f))) —— 每个流都在给底层流"加料"。 对比代理模式：结构相同，意图不同（装饰器=增强功能，代理=控制访问）。
代码联动 · 加料时看这行
public abstract class CondimentDecorator extends Beverage {
    protected final Beverage beverage;   // 被装饰者（可能已加过料）

    public double cost() {
        return beverage.cost();          // 默认：直接转发里层
    }
}

public class Milk extends CondimentDecorator {
    public Milk(Beverage beverage) { super(beverage); }

    public double cost() {
        return beverage.cost() + 4.0;    // ★ 里层价格 + 我的加价
    }
}

public class Sugar extends CondimentDecorator {
    public Sugar(Beverage beverage) { super(beverage); }

    public double cost() {
        return beverage.cost() + 1.0;    // ★ 里层价格 + 我的加价
    }
}

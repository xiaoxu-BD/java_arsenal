观察者模式 Observer 行为型

一句话核心：一对多依赖、状态变更自动广播 —— 天气站不认识观察者，观察者随进随出互不拖累

交互舞台 · 天气站广播

WeatherStation（被观察者 / Subject）

temperature=null, humidity=null（还没收到数据）
当前订阅者：0 个
↓ 只对"已订阅"的观察者广播 ↓
核心规则
  • 松耦合：天气站只知道"名单上有一堆 Display 接口"，不知道对方是手机还是大屏、update 之后要干什么
  • 动态订阅关系：register/remove 运行时增删；退订后广播到不了它（点退订再广播试试）
  • 开闭原则：新增"手表"显示端，天气站代码零修改 —— 每个观察者各干各的（发短信/刷新大屏）
日常同款：GUI 监听器、Spring ApplicationEvent、MQ 广播。 工程版（按事件类型订阅 + 异常隔离）见 advanced/observer 的 EventBus。
代码联动 · 广播时循环逐个高亮
public class WeatherStation {
    private final List<Display> displays = new ArrayList<>();

    public void register(Display d) { displays.add(d); }      // 订阅
    public void remove(Display d)   { displays.remove(d); }   // 退订

    public void measurementsChanged(double t, double h) {
        for (Display d : displays) {          // 只面向接口广播
            d.update(t, h);                   // 观察者各自决定干什么
        }
    }
}

public class PhoneDisplay implements Display {
    public void update(double t, double h) {
        System.out.println("[手机] 当前 " + t + "℃");   // 各干各的
    }
}

工厂模式 Factory 创建型

一句话核心：把 new 收口到一处。三兄弟：简单工厂（一个静态方法）→ 工厂方法（一产品一工厂）→ 抽象工厂（一族一起造）

交互舞台 · 你是调用方，只管"要产品"
调用方
→
SimpleFactory.create("circle")
→
Shape 产品
产品会画在这里（调用方拿到的都是 Shape 接口）
工厂方法：具体工厂阵容（新增产品 = 新增一个工厂类）
CircleFactorycreate() → new Circle()
SquareFactorycreate() → new Square()
核心规则
  • 调用方面向接口：只认识 Shape，不关心背后是哪个具体类、怎么 new 出来的
  • 造对象收口：产品的创建集中一处，产品类名变更时调用方零改动
  • 开闭原则分水岭：简单工厂加产品要改旧 switch（✗ 对修改开放）；工厂方法加产品只加新类（✓ 对扩展开放）
抽象工厂再进一步：一个工厂一次造"一族"（同品牌的外设全套），见源码 FactoryDemo 第 3 段。 JDK 同款：Calendar.getInstance()、Executors.newFixedThreadPool()。
代码联动
public class SimpleFactory {
    public static Shape create(String type) {
        return switch (type) {
            case "circle"   -> new Circle();      // 造圆形
            case "square"   -> new Square();      // 造正方形
            case "triangle" -> new Triangle();    // 造三角形
            case "hexagon"  -> new Hexagon();     // 新增六边形：必须改这里 ✗
            default -> throw new IllegalArgumentException(type);
        };
    }
}

// 调用方：完全不知道 Circle/Square 的存在
Shape s = SimpleFactory.create("circle");
s.draw();
public abstract class ShapeFactory {
    protected abstract Shape create();          // 工厂方法：子类决定造什么
}

public class CircleFactory extends ShapeFactory {
    protected Shape create() { return new Circle(); }
}

public class HexagonFactory extends ShapeFactory {   // ✓ 新增：只加新类
    protected Shape create() { return new Hexagon(); }
}

// 调用方：换产品 = 换工厂，调用方式不变
ShapeFactory f = new HexagonFactory();
f.create().draw();
